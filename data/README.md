# Data contract and access note

No raw or processed data are included. Manchester United supplied the archived `longevity0724` extract and ClubElo ratings; the frozen pipeline also used independently acquired Transfermarkt tables and an author-collected historical extension. Do not publish restricted inputs.

To run the pipeline with independently authorised data, create these local paths. They are all ignored by Git:

```text
data/
├── transfermarkt_public/
│   ├── appearances.csv
│   ├── club_games.csv
│   ├── competitions.csv
│   ├── games.csv
│   └── players.csv
├── club_elo_ratings.csv
├── external/transfermarkt_two_tiers_2000_2025/
│   ├── career_appearances/career_club_appearances.parquet
│   ├── normalized_full/club_seasons.parquet
│   └── normalized_full/players.parquet
├── injuries/longitudinal_2000_2025/   # only for the secondary injury ablation
└── processed/                 # generated by the pipeline
```

Scripts locate this directory with a single idiom, `DATA_ROOT = <root> / "data" if (<root> / "data").is_dir() else <root>.parent / "data"`, so the same file works both here (where `data/` sits beside `src/`) and in the development workspace (where it sits one level up).

The final pipeline requires match dates, competition IDs, player/club IDs, minutes played, player metadata and dated ClubElo ratings. Injury-event variables are not used. Extension files are required to reproduce the complete 13-league 2000-2025 panel.

Before use, check identifier mapping across sources, confirm two club sides and the availability/source of each pre-match Elo value for retained matches, preserve dates and source season labels, and review all licensing, contract, privacy and access restrictions. Direct Elo observations must precede the match by at least one calendar day; same-day observations are not valid inputs.
